## 3. Documentation Format Standard

### 3.1 Heading Hierarchy

#### 3.1.1 Document Title
Use exactly one top-level heading: `# Document Title`.

#### 3.1.2 Main Sections
Use numbered second-level headings such as `## 1. Main Section`.

#### 3.1.3 Subsections
Use decimal-numbered third-level headings such as `### 1.1 Subsection`.

#### 3.1.4 Detailed Subsections
Use fourth-level headings such as `#### 1.1.1 Detailed Subsection`.

### 3.2 Consistency Rule
Numbering must follow the hierarchy continuously. Unnumbered `##`, `###`, or `####` headings are not used in project documentation.

## 4. Working Rule

### 4.1 Research Before Implementation
Research and design decisions are documented before implementation. Reference sites may inspire principles, but the final design remains original and property-specific.

### 4.2 Truth Before Marketing
Unverified amenities, awards, room facts, direct-booking perks, or experiences must not be presented as current property facts.

### 4.3 Scope Before Coding
Codex implementation starts from approved documentation and acceptance criteria so feature scope and visual decisions do not drift during development.
